# data/output/raking

`data/code/raking_NTUWS.R` 每執行一次，就在這裡建一個以樣本命名的資料夾（`wave` 模式用波次名，`member` 模式固定叫 `member_pooled`）。

以下用 `<樣本>` 所代表拿來作為weight的NTUWS樣本資料。
檔案結構：
```
<樣本>/
  weights_<樣本>.csv
  dist_<樣本>.csv
  dist_<樣本>_<變數>.png
  collapse_<樣本>_<變數>.png
  diagnostics_<樣本>.txt
```

---

## weights_&lt;樣本&gt;.csv —— 權數(Weighting)

這是主要產物。一列一個受訪者，用 id 併回分析資料(NTUWS所採用的樣本)即可。

| 欄位 | 內容 |
|---|---|
| `memberId` | 受訪者識別碼 |
| `caseid` | 流水號|
| `weight` | **權數**。平均為 1，總和等於納入 raking 的人數 |
| `excluded_reason` | 沒被納入 raking 的原因，例如「edu 缺值」；有權數的人這欄是空的 |

`weight` 為空表示這個人在某個 raking 變數上缺值，整個個案被排除。做加權統計時記得一併排除。

---

## dist_&lt;樣本&gt;.csv —— 分布對照表

每個變數 collapse 之後，母體、raking 前、raking 後三者的分布。

| 欄位 | 內容 |
|---|---|
| `variable` | 變數 |
| `in_raking` | 這個變數有沒有實際參與 raking |
| `collapse_version` | 用了哪個合併版本 |
| `label` | 類別 |
| `n_sample` | 該類別的人數（未加權）|
| `pct_sample` | raking 前的百分比 |
| `pct_target` | 母體的百分比 |
| `pct_raked` | raking 後的百分比 |

**怎麼看**：`in_raking = TRUE` 的變數，`pct_raked` 應該非常接近 `pct_target`（差距接近 0），否則就是沒收斂——通常是權數上限 `cap` 卡住了。

`in_raking = FALSE` 的變數不會被拉平，`pct_raked` 與 `pct_target` 的差距正是有意義的資訊：它顯示「只靠人口學變數加權，能不能順帶修正這個變數的偏誤」。差距如果還是很大，表示這個變數的偏誤不是人口組成造成的。

## dist_&lt;樣本&gt;_&lt;變數&gt;.png —— 分布圖

`dist_<樣本>.csv` 的視覺版，一個變數一張，三組長條並排：

- **母體**（紅）
- **樣本（raking 前）**（灰）
- **樣本（raking 後）**（藍）

只要 `TARGET_FILES` 有指定母體、而且樣本裡問得到的變數都會出圖，**不限於實際參與 raking 的那些**。沒參與 raking 的圖，標題會標注「【未納入 raking】」。

看的方式：藍色貼齊紅色 = 有效；藍色仍離紅色很遠 = 沒收斂（參與 raking 者）或本來就修正不了（未參與者）。

## collapse_&lt;樣本&gt;_&lt;變數&gt;.png —— 類別合併前後對比

上下兩個面板：

- **上**：母體檔的原始類別
- **下**：套用 `COLLAPSE` 設定合併之後的類別

每個面板都有母體（紅）與樣本（灰）兩組長條，百分比各自以自己的有效樣本為分母。

用途是檢查合併有沒有把重要的差異抹掉。舉例來說，情感溫度計原始 11 類時可能看得出樣本在「5 分」明顯偏少，一旦併成 3 類就看不到了——這張圖讓你在決定合併版本前先看清楚代價。

**沒有做任何合併的變數不會產生這張圖**（畫出來上下兩排會一模一樣），執行時畫面會說明略過了哪些。

## diagnostics_&lt;樣本&gt;.txt —— 診斷紀錄

完整的執行紀錄，出問題時先看這個。裡面依序有：

- 樣本名稱與基準年、原始列數
- **偵測到的欄位**（哪個變數對到哪一欄）
- 補值來源與補了幾筆
- 重複 id 的處理結果
- 每個變數的 collapse 版本、類別數、**NA 人數與比例**、類別清單
- 自動退回較粗版本的紀錄（若有）
- 完整個案數，以及因缺值排除了幾人
- anesrake 的警告訊息
- 實際納入 raking 的變數
- **權數的 min / max / mean / sd**
- **design effect** 與有效樣本數
- raking 後與母體的最大差距（納入與未納入者分開列）
- 觸到權數上限 `cap` 的人數
- anesrake 自己的 summary（各變數 raking 前後的差距）

### 三個關鍵指標

| 指標 | 怎麼判讀 |
|---|---|
| **raking 後與母體的最大差距** | 接近 0 表示收斂良好。明顯大於 0 通常是 `cap` 綁住了——某個類別在樣本裡人太少，就算每個人都吃滿權數上限也補不到母體比例 |
| **design effect** | 權數的離散程度。有效樣本數 = N / deff。超過 2 就要留意，代表加權後的統計檢定力比原始樣本數看起來的低不少 |
| **觸到 cap 的人數** | 比例高表示 raking 被上限限制住。可以調高 `cap`（代價是少數個案影響力變大），或改用較粗的 collapse 版本 |
